# NorthStar CX

**Customer 360 & Next Best Action Engine — built on Snowflake Cortex**

NorthStar CX unifies structured customer data (policies, claims) and unstructured data (call transcripts) into a single evidence-backed record, then produces an auditable churn-risk assessment and next-best-action recommendation — built for insurance and lending teams that need explainable AI decisions, not black-box scores.

Built for the **Snowflake CoCo CLI Hackathon — GCC Edition**, Customer 360 and Next Best Action Engine challenge.

## The problem

Retention and risk teams in insurance/lending sit on two disconnected data sources: structured policy/claims systems and unstructured call transcripts. Neither alone tells the full story, and generic AI recommendations are hard to trust in a regulated environment because they can't be traced back to specific evidence. NorthStar CX unifies both signal types and makes every recommendation auditable.

## Architecture — four chained Cortex-powered skills

```
Customer ID
    │
    ▼
[1] customer_360_assemble  — pulls structured (policies, claims) + unstructured
    │                         (call transcripts) data, filtered by customer_id,
    │                         and synthesizes a unified profile via Cortex COMPLETE
    ▼
[2] churn_risk_score       — scores retention risk (Low/Medium/High, 0-100) with
    │                         reasoning tied to specific evidence, not a black box
    ▼
[3] next_best_action       — recommends one specific action from a defined set,
    │                         justified against the risk assessment and evidence
    ▼
[4] action_audit_trail     — renders the full decision as an audit-ready record:
                              exact policy/claim/interaction IDs, model used,
                              timestamp, and the full reasoning trail
```

Each skill is independently callable and testable (`skills/*.py` can each be run standalone), and they chain together through `app.py` for the end-to-end dashboard experience. This modularity is deliberate — a real risk/ops team could invoke any single skill on its own, not just the full pipeline.

## Tech stack

- **Snowflake Cortex** (`COMPLETE`) — the reasoning engine behind all four skills
- **Snowflake** — structured tables (`CUSTOMERS`, `POLICIES`, `CLAIMS`, `INTERACTIONS`)
- **CoCo (Cortex Code)** — used during development to explore the schema and write/verify SQL (see `setup.sql` for CoCo-authored queries)
- **Streamlit** — the customer-facing dashboard (`app.py`)
- **Python** (`snowflake-connector-python`) — orchestrates the skill chain

## Data

Synthetic dataset generated by `generate_data_v2.py`: 120 customers, 205 policies, 116 claims, 294 call transcripts (`data/`). Sentiment in the transcripts is deliberately correlated with real claim/policy outcomes (denied claims and lapsed policies skew toward negative-sentiment calls), so the churn-risk skill has genuine signal to detect rather than noise.

`data/ground_truth.csv` is a held-out label set (never loaded into Snowflake, never seen by the LLM) used only in `score_accuracy.py` to measure the pipeline's real-world accuracy.

## Results

Scored against all 120 customers in `ground_truth.csv`:

| Metric | Score |
|---|---|
| Accuracy | 87.5% |
| Precision | 67.4% |
| **Recall** | **96.7%** |
| F1 Score | 79.5% |

The pipeline correctly identifies 29 of 30 truly at-risk customers (96.7% recall) — deliberately tuned toward catching real risk over minimizing false alarms, the right tradeoff for retention-critical decisions where a missed at-risk customer is costlier than an unnecessary check-in.

## Running it locally

```bash
pip install -r requirements.txt
# Set up .env with your Snowflake account, user, PAT, warehouse, database, schema
streamlit run app.py
```

Run any skill standalone for testing:
```bash
python skills/customer_360.py CUST0001
python skills/audit_trail.py CUST0001
```

Score accuracy against ground truth:
```bash
python score_accuracy.py
```
